When an image gets both a `width` and a `height`, `fit` decides how a source of another aspect ratio goes into that box. The same 3:2 photo, asked for as a 480 × 480 square:

```twig
<twig:Picasso:Image src="meeting.jpg" width="480" height="480" fit="contain" alt="…" />
```

| Fit                   | Keeps the whole image | Output is exactly `width` × `height` | Use it for                                                |
| --------------------- | --------------------- | ------------------------------------ | --------------------------------------------------------- |
| `contain` _(default)_ | yes                   | no, one side may be shorter          | Photos in content, product shots, anything not to cut     |
| `cover` / `crop`      | no, the excess is cut | yes                                  | Cards, avatars, grids of thumbnails of the same size      |
| `fill`                | yes                   | yes, padded with bands               | Fixed-size slots where cropping is not an option (logos…) |

## Choosing

- **A grid of cards** whose images must line up: `crop`, and give every image the same `width` and `height`.
- **An avatar**: `crop` on a square box.
- **A photo in an article**: keep `contain`, and give only a `width` (the height follows the source ratio), so the browser reserves the right space.
- **A logo in a fixed slot**: `fill` keeps it whole. Prefer a transparent PNG or WebP there: the bands are then transparent rather than white.

Set the default for every image with [`default_fit`](/reference/configuration/#default_fit), and override it per image with the `fit` prop or the `fit` argument of [`picasso_image_url()`](/reference/twig-functions/).

:::note[With Imgix]
[Imgix](/transformers/imgix/) maps the same values to its own modes: `contain` to `clip`, `cover` and `crop` to `crop`, `fill` to `fill`, which pads like Glide does. Any other value is passed to Imgix unchanged.
:::
